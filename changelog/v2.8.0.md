# Outlet Radar v2.8.0 — Anonymous outbound click counts

## What it adds
- When a visitor opens a store listing from **Compare offers**, the browser quietly reports the click to `/api/click`. The link itself is a normal direct link: nothing is redirected through Outlet Radar, so it cannot slow down or break a purchase, and it cannot be used as an open redirect.
- Only a **daily counter** per store, link host and product title is kept in the new `offer_click_daily` table. No IP address, cookie, user agent or full URL is stored.
- `/admin/providers` has a new **Outbound clicks** section: top stores and most clicked products over the last 7 days. This shows which retailers and models actually drive traffic, which is the data needed to choose affiliate programs to join and searches worth keeping warm.
- The endpoint is anonymous, so it is hardened: it only accepts known sources and http(s) links, ignores bad input, always answers 204, and creates at most 5,000 new rows per day (existing rows keep counting).

## Migration and configuration
- Run `db/migrations/005_offer_click_daily.sql` in Neon (additive, repeatable). Without it the app works normally; clicks are simply not recorded and the dashboard says so.
- No new environment variables.

## Validation
- Production build and TypeScript check pass.
- 85 scenario checks pass against PostgreSQL with mocked providers, including: repeated clicks incrementing one row, only the host being stored, invalid input recording nothing, the daily row cap, and the admin report.
- Not exercised in a real browser. The page uses `navigator.sendBeacon` with a `fetch(..., { keepalive: true })` fallback.
