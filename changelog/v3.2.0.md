# Outlet Radar v3.2.0 — Optional bulk feed ingestion (Impact)

## What it adds
- **Bulk ingestion of Impact advertiser catalogs** into the shared catalog, so catalog browse can show brand and store offers (adidas, New Balance, Puma and so on, for the programs that approved your account) with no live call per search. It is **off by default**.
- A **Bulk feed ingestion** section on `/admin/providers`:
  - **Preview Impact feeds** lists the catalogs your account can see, marks the selected ones, and reads one page of a catalog (2 Impact calls) to show the item fields, how many items pass the item filter, and a few example products. It writes nothing. Use it to check the data before turning ingestion on.
  - A status table per catalog: next page, items read, products saved, full cycles, last run, last error.
- How it works: each scheduled run reads a few pages per selected catalog (`FEED_PAGES_PER_RUN`, default 2, 250 items per page; one Impact budget unit per page) and remembers where it stopped (`feed_ingest_state`), so a large catalog is covered over several days. The daily warm-up job runs a batch; `GET /api/cron/ingest-feeds?pages=N` (CRON_SECRET) runs more on demand or from a GitHub Actions schedule.
- Items are kept only when category + name match the item filter (default: footwear; override with `FEED_ITEM_REGEX`) and have a brand and link. Variants of one product at one store are collapsed into one listing: sizes are the in-stock variants, the price is the lowest, discounts are captured, fully sold-out products are skipped.
- Feed offers are kept for 7 days and pruned 3 days after they expire. Ingestion stops when the database reaches `FEED_MAX_DB_MB` (default 350 MB; Neon's free plan allows 512 MB).
- In Compare offers, fresh live Impact results replace the same store's older feed-ingested row and Channel3's plain link.

## Fix (from v2.4)
- Nike.com offers were saved to the catalog but dropped when the catalog was read back, so later searches answered from the saved catalog never showed them. They now do.

## Migration and configuration
- Run `db/migrations/006_feed_ingest_state.sql` in Neon.
- Off unless `FEED_INGEST_ENABLED=true` and `IMPACT_FEED_CATALOG_IDS` lists the catalogs (ids come from **Preview Impact feeds**). Optional: `FEED_PAGES_PER_RUN`, `FEED_MAX_DB_MB`, `FEED_ITEM_REGEX`.

## Validation
- Production build and TypeScript check pass.
- 118 scenario checks pass against PostgreSQL with mocked providers, including ingestion that is off by default, footwear-only filtering, variant collapsing, in-stock sizes only, 7-day expiry, cursor resume and wrap-around, no duplicates on re-read, browse returning ingested products, the storage guard, pruning, budget limits, the preview writing nothing, and the manual and warm-up routes.
- Not exercised against the live Impact API. The catalog item endpoint, pagination fields (`@numpages`) and item fields (`Name`, `Manufacturer`, `Url`, `CurrentPrice`, `Size`, `StockAvailability`, `Category`, `Mpn`) follow Impact's published reference but were not confirmed against a real account. If **Preview Impact feeds** shows an error or unexpected fields, send me the output and I will adjust the mapping before you enable ingestion.
