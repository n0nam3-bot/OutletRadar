# Outlet Radar v3.7.0 — The test suite ships with the repo

## What it adds
- **`npm test`** runs all 227 automated checks in under a minute against the real application code: the search pipeline, caching and budgets, every provider integration (with simulated responses), feed ingestion, size matching, saved searches, affiliate links, the privacy/robots/sitemap/header files and the fresh-lookup limiter.
- Checks run on an in-memory PostgreSQL (PGlite), so no Neon account, network access or API keys are needed. The full schema and **every migration** are applied twice to prove they are repeatable; new migrations are picked up automatically.
- `tests/README.md` explains what each file covers and how to run one.
- Until now these checks only ran in the build environment used to create the releases; now you (or any developer) can run the same checks before applying an update, and future changes can be checked against them.

## Changes to the app
- `lib/db.ts` gained a tiny `setTestDatabase` hook that only the tests call. Behavior with a real `DATABASE_URL` is unchanged.
- `package.json`: a `test` script and two development-only packages (`tsx`, `@electric-sql/pglite`). They are not part of the production bundle, but the update workflow's `npm install` now also installs them (a few seconds longer).
- `tsconfig.json` excludes `tests/` so the production build does not type-check them.

## Not covered by the tests
- Real provider responses (the connection test and feed preview on `/admin/providers` cover those), the browser, and Vercel's network and CDN.

## Optional
- To run the tests as part of every update, add `npm test` after the build step in `.github/workflows/apply-update-zip.yml`. That file can only be edited by hand in GitHub, not through the update ZIP.

## Migration and configuration
- No database migration. No new variables.

## Validation
- `npm test`: 227 checks passed across 5 files (144 pipeline, 39 size, 17 saved-search, 14 legal, 13 limiter).
- Production build passes with the new files and packages.
