# Outlet Radar v2.3.0 — Never-empty search and free-tier resilience

## The problem this fixes
On free provider plans the site-wide allowance is small (PCKT 12.5 credits/day made about five uncached sneaker searches a day). Worse, when the allowance ran out, the empty or partial answer was cached for 12 hours under that exact search, so the search stayed blank even after the allowance reset.

## Changes
- **Incomplete answers are never cached.** A result produced while a source was out of budget, paused, failing or skipped is no longer written to the 12-hour exact-query cache. Sources that did succeed keep their own 24-hour/6-hour snapshots, so the next attempt only re-asks the missing sources. The cache namespace is bumped to `catalog:v8`, which discards any previously cached empty result.
- **Never a blank page.** When a source cannot be queried live, its expired snapshot (up to 30 days old) is shown and labelled "stale". If nothing matches at all, the app shows a saved copy of the exact search, then the closest saved products (any matching words, best matches first). A notice banner explains what is being shown.
- **Cheaper browsing.** Flight Club (1.0 credit) and Kicks Crew (0.5) are queried during a visitor's browse only while at least half of today's PCKT allowance remains. StockX and GOAT (0.7 combined) always run. Skipped sources are completed later by the warm-up job.
- **Shorthand shares a cache entry.** `aj1`, `af1`, `am90`, `nb`, `dunks`, `yeezys` and similar are expanded before caching and provider requests, so equivalent searches cost one lookup.
- **Refresh queue and scheduled warm-up.** Incomplete searches are queued (`catalog_refresh_queue`). A new daily job, `/api/cron/warm-catalog`, completes queued searches (most requested first) and then refreshes popular seed searches, using at most 40% of the day's budget so visitors keep priority.
- **Budgets are configurable.** Daily/monthly ceilings can be overridden with environment variables. Default daily ceilings rise to PCKT 15 (450 ÷ 30) and SerpApi 7; monthly ceilings are unchanged (450 and 200).
- **Admin dashboard** shows the refresh queue; `/api/admin/providers` returns its statistics.
- Catalog discovery moved from `app/api/catalog/route.ts` to `lib/catalog-discovery.ts` so the public route and the warm-up job share one code path. The public API is unchanged except for extra response fields (`notice`, `complete`, `incomplete`, `approximate`, `savedSearch`, `queued`) and two new source statuses (`stale`, `skipped`).
- Documentation reorganized: release notes live in `changelog/`, operational guides in `docs/`.

## Migration and configuration
- Run `db/migrations/004_catalog_refresh_queue.sql` in Neon (additive, repeatable). The app still works without it; only the queue is disabled.
- `vercel.json` adds a second daily cron (`/api/cron/warm-catalog`, 05:47 UTC). Vercel Hobby allows daily crons.
- New optional variables: `PCKT_DAILY_BUDGET`, `PCKT_MONTHLY_BUDGET`, `SERPAPI_DAILY_BUDGET`, `SERPAPI_MONTHLY_BUDGET`, `APISH_DAILY_BUDGET`, `APISH_MONTHLY_BUDGET`, `WARM_DAILY_SHARE`.

## Validation
- Production build and TypeScript check pass.
- Migrations 001-004 and the full schema apply twice without error on PostgreSQL (PGlite).
- Scenario tests against PostgreSQL with mocked providers: budget exhaustion, stale snapshots, saved-copy and closest-match fallbacks, optional-source skipping, no caching of incomplete answers, queue completion, warm-up budget share, warm-up authorization, and strict model matching (`Jordan 1` does not match `Jordan 14`).
- Not exercised against live PCKT/SerpApi/Neon services.
