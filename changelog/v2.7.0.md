# Outlet Radar v2.7.0 — Live connection test

## What it adds
- `/admin/providers` has a **Run connection test** button. It sends one real "Air Jordan 4" search to each configured provider (PCKT StockX, SerpApi Google Shopping, API.SH Nike, Channel3, eBay, Impact) and shows, for each: connected or not, the exact error message if it failed, how many results came back, how long it took, the credits used, and **which stores it returned**.
- Below the results, a checklist shows which of your target stores (StockX, GOAT, Flight Club, Kicks Crew, Nike, Foot Locker, JD Sports, Jimmy Jazz, Champs Sports, Finish Line, Snipes USA, Macy's, Bloomingdale's, eBay) came back through which provider for that search. Results vary by product, so try the same test again after changing nothing else, or use Compare offers on other products.
- The test uses about one credit per provider (0.4 for PCKT). Each probe reserves its normal budget first, so the usage counters stay accurate. It does not touch the circuit breakers, caches or catalog, and is limited to one run every 20 seconds.
- Endpoint: `POST /api/admin/providers/test` (requires `CRON_SECRET`).

## Why
Most provider integrations were built from the providers' published documentation and tested against simulated responses. This lets you confirm each live connection in your own deployment in one click and, if one fails, see the provider's own error message.

## Migration and configuration
- No database migration. No new environment variables.

## Validation
- Production build and TypeScript check pass.
- 79 scenario checks pass against PostgreSQL with mocked providers, including: secret required, all six providers probed, merchant and store lists reported, budget counters updated, nothing cached or stored, and rate limiting.
- Not run against live providers (that is what the button is for).
