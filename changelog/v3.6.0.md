# Outlet Radar v3.6.0 — One runaway visitor can no longer use up everyone's daily allowance

## The risk
The daily provider allowance is shared. Anyone, or any bot, could run many different searches in a row and spend all of it, leaving every other visitor with saved results for the rest of the day.

## What it adds
- **Per-connection fresh-lookup limit.** A search that has to ask a live provider (it was not answered by the CDN, a cache or the saved catalog) now counts as one "fresh lookup" for the connection that made it. A connection may make `LIVE_LOOKUPS_PER_HOUR` of them per hour (default 15; 0 turns the limit off). Normal visitors do not come close, and searches answered from a cache or the saved catalog never count.
- **Nobody is blocked.** Past the limit the search is still answered, with saved, stale or closest results, a clear notice ("You have run many fresh lookups in the last hour..."), and it is queued so the daily warm-up completes it. Answers are marked `limited: true` in the API response and cached at the edge for only 30 seconds.
- **Counts stay in memory.** The connection address (from the proxy headers) is used transiently as a counter key in the server's memory. Nothing is saved, logged or written to the database, and the table is bounded at 20,000 entries. The privacy page now says so.
- A request with no readable address is never limited.

## Honest limits
- Each server instance counts on its own, so this is a best-effort guard, not a security boundary. A determined attacker can spread requests across addresses. For real abuse protection, also turn on Vercel's firewall and rate limiting in the Vercel dashboard.
- It protects the shared credits; it does not stop someone from loading the CDN-cached pages.

## Migration and configuration
- No database migration.
- Optional variable: `LIVE_LOOKUPS_PER_HOUR`.

## Validation
- Production build and TypeScript check pass.
- 13 unit checks for the limiter (15 per hour, per-connection isolation, reset after an hour, unknown address never limited, configuration and invalid values, header parsing, bounded memory) and 11 integration checks (no provider call or budget spend when limited, one decision per search, closest saved results still returned and queued, honest notice and source messages, not cached for 12 hours, normal searches unaffected, cache and saved-catalog answers never count, route-level behavior for two addresses, 30-second edge cache).
- Existing suites: 144 pipeline (133 + 11), 39 size, 17 saved-search and 14 legal checks pass.
