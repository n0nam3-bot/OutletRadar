# Outlet Radar v2.5.0 — eBay listings in Compare, database-free page health check

## eBay Browse API
- **Compare offers** now also searches eBay (when configured) for **new, fixed-price** listings of the exact product and shows up to three, cheapest first. eBay's free developer allowance is 5,000 calls per day (app ceiling 3,000/day, `EBAY_DAILY_BUDGET`), far above the other sources, and it costs one call per comparison.
- Matching reuses the strict model matching (every model word and the same model numbers) or a matching manufacturer style code in the title, so other colorways and other models are excluded.
- Listings are independent sellers, so each states the seller (with feedback score where eBay provides it) and reminds shoppers to confirm size, condition and authenticity.
- Optional `EBAY_CAMPAIGN_ID` (eBay Partner Network) makes eBay return affiliate links, which are then used for the listing URLs.
- Like Channel3, eBay data is live-only: cached for 3 hours, never saved to the normalized catalog, and an incomplete eBay result (budget reached, paused, error) is not cached. Review eBay's API License Agreement before monetizing.
- When eBay is configured, eBay rows from Channel3 are skipped to avoid duplicates.

## Page health check no longer wakes Neon
- The web page called `/api/health` on every load, and that route ran a database query, so each visit used Neon compute. The page now calls `/api/health?light=1`, which reports configuration only and never touches the database. The full check (`/api/health`) is unchanged and now also reports `databaseConfigured`, `productSearchConfigured`, `channel3` and `ebay`.
- Side effect: the page previously read two fields the endpoint never returned, so the watchlist "saved" message always assumed Neon was not configured. It now reflects the real configuration.

## Migration and configuration
- No database migration.
- New optional variables: `EBAY_CLIENT_ID`, `EBAY_CLIENT_SECRET`, `EBAY_CAMPAIGN_ID`, `EBAY_DAILY_BUDGET`, `EBAY_MONTHLY_BUDGET`.

## Validation
- Production build and TypeScript check pass.
- 60 scenario checks pass against PostgreSQL with mocked providers, including eBay sign-in (Basic auth, client-credentials grant), the NEW/fixed-price filter, the affiliate header, exact-product filtering, cheapest-first ordering, budget exhaustion, no catalog persistence, and the database-free health check.
- Not exercised against live eBay, Channel3, API.SH, PCKT, SerpApi or Neon. The eBay request and response shapes follow eBay's published Browse API documentation; verify with one real Compare after adding the keys.
